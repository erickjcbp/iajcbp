O que é esta pasta?
-------------------
É a "memória escrita" do projeto: o que ainda falta, o que já foi
feito, o histórico do banco e os planos de cada funcionalidade.
Aqui NÃO roda nada sozinho — é leitura, para entender decisões.

Arrumada em 16/09/2026.


POR ONDE COMEÇAR
----------------
  pendencias.md  ->  A LISTA. Abrir AQUI antes de decidir o que fazer.
                     São 3 partes: o que falta, o que NUNCA se deve
                     fazer (evita repetir erro caro), e um link para
                     o histórico.

                     Regra: uma coisa só sai da lista quando foi feita
                     E CONFERIDA — nunca por ter sido commitada.

  pendencias-fechados.md  ->  O HISTÓRICO. Dia por dia, o que era o
                     problema, qual era a causa e como foi provado.
                     Serve para quando um problema parecido voltar.


AS QUATRO SUBPASTAS
-------------------

1) docs/migrations/   —  HISTÓRICO DO BANCO DE DADOS
   Cada arquivo .sql é uma "migration": uma mudança na ESTRUTURA do
   banco (criar tabela, adicionar coluna, mudar permissão), na ordem
   em que foram aplicadas. Os números no início dão a sequência.
   Hoje são 37 arquivos, da 001_base_schema até a 066_recado_da_foto.

   REGRA DE OURO: nunca edite uma migration antiga já aplicada.
   Para mudar algo, crie um arquivo NOVO com o próximo número.

2) docs/provas/   —  OS TESTES DO BANCO
   Arquivos "provar-XXX.sql". Cada um confere se uma migration fez
   o que prometeu — rodando de verdade, não por leitura. Ficam
   VERMELHOS se alguém afrouxar ou apertar demais uma permissão.
   Rodar assim:  psql "$SUPABASE_DB_URL" -f docs/provas/provar-XXX.sql
   O número do arquivo casa com o número da migration que ele prova.

3) docs/anotacoes/   —  BILHETES DE UMA ÉPOCA
   Anotações pontuais, com a data no nome. Não são a lista nem o
   histórico: são recados que fizeram sentido num dia específico.
   Se um deles disser "apagar em tal data", é para apagar mesmo.

4) docs/superpowers/   —  PLANOS E ESPECIFICAÇÕES
   plans/  -> o passo a passo de cada entrega (cadastro de família,
              landing da pastoral, missões...).
   specs/  -> a ideia por trás de cada funcionalidade: o porquê e o
              desenho da solução, antes de programar.
   O nome começa com a data, então dá para ler na ordem do tempo.


Para iniciante: o que significam essas palavras?
------------------------------------------------
  - Migration : uma mudança no banco salva como arquivo, em ordem.
                Serve para qualquer pessoa montar o mesmo banco do
                zero, só rodando os arquivos na sequência.
  - RLS       : a regra que decide QUEM pode ver ou mudar cada linha
                do banco. É o que impede um acólito de ver a ficha
                de outro.
  - Markdown (.md) : jeito simples de escrever texto com títulos,
                listas e negrito usando símbolos (#, -, **).
